A2 Case Study Stage 1 student resource

# SmartCare scenario

SmartCare Community Clinic currently uses spreadsheets and paper records to manage patients and appointments. The client says: 'We need software to help manage patients, practitioners and appointments.' This is not yet a complete specification.

# Initial Engineering Brief

## 1\. Problem summary

Write approximately 100 words.

SmartCare Community Clinic currently uses an out-of-date system for managing patients and appointments. The current system uses spreadsheets and paper records to manage information and manual processes for booking and canceling appointments. This system has caused many issues such as duplicate appointment bookings, difficulty locating patient records, and inconsistent and unreliable information. Because of these issues, SmartCare Community Clinic is looking for a simple software system to initially support patient, practitioner and appointment management.

## 2\. Initial stakeholders

| Stakeholder   | Possible need                                                                                                          |
| ------------- | ---------------------------------------------------------------------------------------------------------------------- |
| Patients      | The ability to manage their appointments.                                                                              |
| Admin Staff   | The ability to manage patient appointments and information.                                                            |
| Clinic Staff  | The ability to check information about appointments and information about the patients.                                |
| Practitioners | The ability to check when they are required for appointments and the ability to view information about their patients. |

## 3\. Initial features

| Feature                                                  | Confirmed or provisional? | Why?                                                                                                                                                                   |
| -------------------------------------------------------- | ------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Ability to record patient information                    | Confirmed                 | This feature is essential for managing patients.                                                                                                                       |
| Ability to book appointments using patients' information | Confirmed                 | This feature is essential for patients to book the appointments.                                                                                                       |
| Ability to view information about practitioners          | Provisional               | This feature would help with figuring out when certain practitioners are available. This also could be replaced with just letting patients know if they are available. |
| Login system for patients                                | Provisional               | Would help patients with the process of booking appointments but is not currently specified in the brief.                                                              |

## 4\. Questions for the client

1\. Will the software need to persistently store the information?

2\. Will this software be used by patients to book appointments or will it just be used for staff to manage appointment information?

3\. What information will this software store about patients, practitioners, and appointments?

4\. Will the software need a system to transfer information from paper copies and spreadsheets to the software?

5\. What would the target user of this software be? Tech literate?

## 5\. What we do not yet know

1\. What functions the software will be built to do. E.g. allowing patients to book and cancel appointments.

2\. How do they want to manage patients, practitioners, and appointments?

3\. What is the scale of this software?

# AI Activity Card - Ask, Check, Explain

## Before AI

What do I think the code does? What problems can I already identify?

## AI request

Act as a tutor. Explain this code and identify potential problems. Do not provide a complete replacement. Ask me questions that help me reason about the solution.

## Evaluate

## Decide

For each significant suggestion: Accept / Modify / Reject / Keep unverified.

## Verify

- Run the code
- Test normal input
- Test unusual input
- Compare with requirements
- Ask tutor/peer
- Check documentation

## Explain

Can I explain the final code without reading the AI response? What do I still need to understand?
